Sprint Zero · worked example · Minimal

What got built, and how it kept going

One Sprint Zero run against Notion produced a real shared-workspace MVP in about twenty minutes. Everything after that — twelve rounds of features, one at a time, in conversation — is the part this record is really about.

Reference: notion.so Stack: node-react · local (SQLite + self-issued JWT) Level: MVP

The ask

The smallest real version of a team wiki

Notion is a vast product — databases, real-time multiplayer, dozens of block types, granular sharing, templates, a gallery. Sprint Zero was pointed at it and scoped down hard: one shared workspace per team, pages that nest under other pages, three block types to start (text, heading, checklist), and teammates invited by email who can all view and edit the same pages.

Thirteen things were named and excluded up front so the agents couldn't wander: real-time multiplayer editing, granular roles, rich formatting, file uploads, templates, full-text search, version history, public share links, and more — all logged in docs/scope.md. The seed is real: a demo workspace ("Traversaal Team Wiki") with two demo members and a small real page tree — an Onboarding page with two nested sub-pages, and a Team norms page with checklist items already ticked.

The core loop, and what QA found

A user signs up and lands in a workspace. They create a page, nest it under another page, and add text, heading, and checklist blocks. They invite a teammate by email; that teammate signs up (or logs in), sees the same workspace, opens any page in it, and edits a page another member created — visible to everyone on reload.

QA passed 23/23 API integration tests and 19/19 browser steps (full auth dance, core loop, expired-token handling) — and caught one real bug along the way: the "Add block" button stayed disabled after the first block was added, a missing setSubmitting(false) on the success path. Fixed before sign-off.

Part two

Everything added after that, in order

Each of these was requested and built one at a time, in conversation, well past a typical Sprint Zero MVP. The full reasoning for each lives in docs/decisions.md under its own "Amendment" heading — this is the short version, in the order it happened.

  1. "Continue as guest" — a public, read-only view of the seeded demo workspace at /demo, no account needed.
  2. New-workspace example content — every fresh signup now gets a starter page tree instead of a blank workspace, mirroring Notion's own "Getting Started" default.
  3. Color and a real home dashboard — a deterministic color per top-level page, colored status pills in tables, and /app rebuilt as an actual dashboard instead of an empty state.
  4. A real, editable table block — columns, rows, and cells, all persisted, plus richer example content to give the new coloring something to work with.
  5. A mock form builder block — cover, icon, editable fields, Preview/Share UI. At this point still fully mocked, no response storage.
  6. Notion-style row detail view — click "Open" on a table row to see it as its own page: a big title, every other column as a labeled property, plus comments (at this point, local-device-only via localStorage).
  7. Grouped, collapsible home sections — root pages get an optional section field; the dashboard groups them into named, collapsible sections instead of one flat grid.
  8. A monospace code/diagram block, plus a two-page example to demonstrate it, and a code-block example added to the very first page every user sees.
  9. A ten-item batch, all in one pass — page icons; drag-to-reorder blocks and drag-pages-between-sections; sidebar search; page templates (via a generic duplicate-page endpoint); a short page-activity log; poll-based page presence ("who's viewing this page"); real, server-side row comments (replacing the local-only version); page locking (a narrower stand-in for full permissions); and real form responses.
  10. Landing page copy pass — repositioned from "a team wiki" to "inspired by Notion," corrected on request to not claim Minimal is Notion, and em dashes removed from the copy.
  11. Reorganized into its own folder — server/, client/, and docs/ moved into a self-contained project folder, matching the examples/ghost-lite convention used elsewhere in Sprint Zero.
  12. An Obsidian-style knowledge layer — backlinks ("Linked mentions" on every page) and a graph view of the whole workspace, computed live from internal links that already existed as plain substrings in block content. No new storage.

The shape of the final API

Ten resource groups, 31 routes in the current docs/api-contract.md — the MVP contract covered auth, invites, and plain page/block CRUD; tables, row comments, form responses, page locking/activity/presence, and the knowledge graph were added one amendment at a time afterward. Full field-by-field detail lives in docs/api-contract.md.

GroupCovers
AuthPOST signup/login, GET /auth/me
Workspaceinvite by email, list members
Pageslist/create/read/update/delete, duplicate (the template mechanism), locking
Page activity & presencea short human-readable change log; poll-based "who's viewing"
Blockstext, heading, checklist, bulleted_list, table, form, code
Tablescolumns, rows, cells — full CRUD nested under a table block
Row commentsreal, server-side, shared across the workspace
